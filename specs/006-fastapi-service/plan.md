# Implementation Plan: HTTP Service for Bird Recognition

**Branch**: `006-fastapi-service` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/006-fastapi-service/spec.md`

## Summary

Expose search, crop/run/visit reads, `ask` and ingest/index background jobs over a
versioned (`/v1`) FastAPI service that reuses existing domain code. Logic now embedded in
`cli.py` (payload builders, error-code mapping, sanitising, path validation) moves into
importable modules shared by CLI and API, so both produce identical results. The
OpenAPI 3.1 document is generated by FastAPI, exported to a committed file and checked in
CI. Errors use RFC 9457 `application/problem+json`. Long jobs run as managed CLI
subprocesses with file-based job records; read endpoints and `ask` run in-process.

## Technical Context

**Language/Version**: Python 3.14+ (uv-managed)

**Primary Dependencies**: existing stack plus new `fastapi`, `uvicorn` (runtime) and
`httpx`, `openapi-spec-validator` (dev) — **require owner approval before adding**

**Storage**: existing PostgreSQL/pgvector (read-only for the API); job records as JSON files
in an owner-configured directory outside the repository

**Testing**: pytest with FastAPI `TestClient`, fake search/ask services (no network, no
LLM key); OpenAPI contract test; integration tests under the existing disposable-DB opt-in

**Target Platform**: local machine / small LAN, single trusted owner

**Project Type**: CLI-first Python package gaining a secondary HTTP interface

**Performance Goals**: search < 3 s warm (SC-006); job acknowledgement < 2 s (SC-005)

**Constraints**: loopback bind by default; API key for non-loopback; single worker; models
loaded once; never return full frames; no crops sent externally without opt-in

**Scale/Scope**: one owner, a handful of concurrent requests, one active job at a time

## Constitution Check

*GATE: pass before Phase 0; re-checked after Phase 1.*

| Principle | Status | Notes |
|---|---|---|
| I. Evidence-grounded answers | Pass | `ask` reuses `ask.py` and `_ask_payload`; citations and insufficient-evidence statements pass through unchanged. |
| II. Privacy-preserving | Pass | Only privacy-screened crops are served; no frame endpoint; LLM key via env; footage/jobs/reports outside repo; errors sanitised. |
| III. Pretrained models, measured quality | Pass | No training; evaluation/benchmark stay CLI-only. |
| IV. Testable, offline core | Pass | All tests use fakes/mocked LLM; DB tests stay opt-in. |
| V. CLI-first, small scope | **Violation (justified)** | CLI stays primary and complete; HTTP is additive. But V says to avoid authentication unless the constitution is amended; FR-008 requires a shared API key for non-local exposure. See Complexity Tracking. |

**Gate outcome**: pass. Constitution amended to 1.1.0 (2026-11-24) permitting a single
shared API key guard for non-loopback exposure only (no accounts, roles or multi-user
support), so no amendment task remains.

**Post-design re-check**: unchanged. The design adds no accounts, cloud deployment or
streaming; the only authentication is one static key compared in constant time.

```text
src/bird_recognition/

└── api/
    ├── __init__.py
    ├── app.py           # create_app(), lifespan (lazy model/DB handles), router mounting at /v1
    ├── settings.py      # env/CLI settings (host, port, key, jobs dir, allowed roots)
    ├── security.py      # API-key dependency, loopback check
    ├── errors.py        # problem+json models, exception handlers, stable codes
    ├── schemas.py       # Pydantic request/response models
    ├── routers/
    │   ├── health.py
    │   ├── search.py    # POST /v1/search
    │   ├── crops.py     # GET /v1/crops/{id}, /image
    │   ├── runs.py      # GET /v1/runs, /v1/runs/{id}
    │   ├── visits.py    # GET /v1/visits
    │   ├── ask.py       # POST /v1/ask
    │   └── jobs.py      # POST /v1/ingest, /v1/index; GET /v1/jobs, /v1/jobs/{id}
    ├── jobs.py          # JobManager: subprocess launch, file records, interruption recovery
    ├── openapi.py       # export/check helpers
    └── server.py        # `bird-recognition-api` entry point (uvicorn, single worker)
docs/
├── usage.md             # + HTTP service section
├── development.md       # + OpenAPI export/check
└── api/openapi.json     # committed generated description
tests/unit/api/          # per-router tests, security, errors, jobs, openapi contract
tests/integration/api/   # opt-in disposable-DB parity tests
```

**Structure Decision**: single project; a new `bird_recognition.api` package plus two small
extraction modules (`payloads.py`, `paths.py`) so CLI and API share one implementation
(FR-003). A new console script `bird-recognition-api` is added in `pyproject.toml`.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Authentication (shared API key) vs. Principle V | FR-008: LAN exposure must not be open; the service can trigger ingestion and external transmission | Loopback-only would block the stated small-LAN use; no key on LAN is unsafe. Mitigated: one static key, constant-time check, optional on loopback, requires constitution amendment first. |
